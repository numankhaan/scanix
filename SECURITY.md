# Security and privacy

Scanix is a network scanner. Only scan systems you are authorized to test.
Passing automated checks **does not guarantee security or privacy**. TLS service handshakes require TLS 1.2 or newer, including certificate-verification
opt-out mode. Scan evidence,
banners and certificate claims are untrusted; versions alone are not vulnerabilities.

## Reporting and containment

Use GitHub's **Report a vulnerability** / private advisory facility when available.
If unavailable, request a private reporting channel without posting the finding.
Do not open a public issue or PR containing credentials, personal values, real
captures, raw scanner reports, authenticated URLs or exploit-bearing private data.
Report category, severity, repository-relative location/commit and remediation state.
Local gates use ephemeral keyed fingerprints rather than printing matched values.

For an actual credential exposure, its owner must rotate/revoke it through the
provider. Removing a file does not remove history, forks, clones, caches or artifacts.
Do not rewrite history, delete evidence or revoke credentials as an automated fix.
The separate [cleanup plan](docs/SECURITY_HISTORY_PLAN.md) requires owner approval.
No production credential was identified in the initial audit; this is not proof that
none exists. Never use the committed test keys outside disposable loopback tests.

## Gates and severity policy

- Gitleaks and the custom privacy gate block **every new unapproved finding**.
  Missing tools, invalid reports, incomplete/shallow Git history and oversized
  inputs fail clearly, rather than producing a clean result.
- Dependency checks block **all reported runtime advisories**, including those
  without a known fix or severity. Scapy is pinned and has no runtime dependencies;
  `--no-deps --disable-pip` avoids executing requirement/build metadata. Review and
  update this assumption if dependencies change. Tool environments are also audited.
- Bandit blocks medium/high findings; low findings remain visible for manual review.
  CodeQL security-extended blocks severity >=4 or missing severity. Findings are
  uploaded only after SARIF allowlist redaction. Raw SARIF never becomes an artifact. CodeQL database/debug uploads are disabled.
- actionlint failures block. Workflow review also checks event trust boundaries,
  permissions, SHA pins, shell injection and artifact publication.
- When Rust is present, cargo-audit blocks advisories **and warnings**, including
  unmaintained crates; formatting and Clippy warnings also block. Compilation is
  a subsequent trusted CI/static check, not part of the initial read-only audit.

Privacy patterns flag personal home paths, nonpublic email candidates, labeled
phone candidates, authenticated URLs, environment files, capture/report/database
and credential containers, bytecode and unreviewed binaries/documents. Scanix
JSON/CSV/HTML report shapes are flagged independently of the export filename.
Default email regex lengths are bounded, with a long-input regression. IP addresses
and names are **not** automatically classified as private. Reserved fixture email
domains and GitHub's generated noreply identities have documented public purposes.
Other public project identities require explicit review; do not blanket-allow a
personal domain. Binary formats/metadata require separate review, not a clean label.
Checks inspect up to 16 MiB per file/blob; larger content fails for manual handling.

The only secret exceptions are the two exact paths **and SHA256 contents** in
`security/synthetic-keys.json`, for the Gitleaks `private-key` rule alone. These are
public, disposable TLS fixture keys generated by the fixture script, necessary for
trusted/self-signed/expired/mismatch tests. Changing a byte or copying a key to
another path removes the exception. No entire fixture directory is excluded.
Bandit `nosec` annotations identify fixed subprocess usage and a boolean probe-token
field individually. They do not suppress arbitrary subprocesses or credentials.

## Local prevention

See [CONTRIBUTING.md](CONTRIBUTING.md) for installation. Pre-commit scans the entire
**index**, including prospective author/committer identities. Pre-push scans every
outgoing commit snapshot, metadata/message and secret-bearing diff, including
intermediate commits and merge resolutions. A new branch is compared to the fetched
origin default branch; missing refs fail. Fetch before pushing. Existing inherited
objects are reviewed separately, not accepted through a credential baseline.

Hooks are local conveniences and can be bypassed; enforce CI and human review on
GitHub too. Private regexes belong in an external JSON object mapping safe rule IDs
to regexes, referenced by `SCANIX_PRIVATE_PATTERNS`. This is trusted local regex
configuration, limited in count/length; do not commit private values/patterns.
Store raw reports outside the repository in a mode-0700 directory. The private temp
reports created by gates are removed after a run; initial audit evidence is retained
privately. `.gitignore` prevents common accidental additions; it cannot untrack or
remove previously published content, and force-add still needs the gates.

## CI and repository settings

`Security` and `CodeQL` run on **all branch pushes, PRs, weekly schedules and manual
dispatch** (schedules/manual UI activate after the workflows reach the default
branch). Checkouts use full history for the gates. PR ranges use event base/head
SHAs; pushes use before/head, new branches use origin/default. Annotated/nested tag messages and tagger metadata are also scanned; tag pushes
resolve the actual tag object instead of only its commit. Every branch commit
is examined, not just the last; missing old objects fail. A full reachable-history
secret scan runs on every event, with supplementary printable-ASCII binary views
because Git patch output omits binary bodies. This does not decode every format. Historical privacy inventory runs separately each
week/manually and is expected to fail until historical exposure is addressed.
It is **not** a passing scan or an ignored credential baseline. Incremental gates
still block any new personal information. Neither workflow uses pull_request_target.

Tokens have contents-read except the CodeQL job's security-events-write permission;
checkout does not persist credentials. No repository secrets are passed to PR code.
Actions are pinned to upstream-verified full SHAs; the workflow policy gate also
checks pins, permissions, untrusted events, shell interpolation and uploads; scanner downloads use pinned
release digests. No raw audit report/capture uploads exist. The opt-in privileged
lab still validates locally but no longer automatically publishes captures/reports.

At audit time the repository API reported GitHub secret scanning and push protection
**enabled**. Non-provider patterns/validity checks and Dependabot security updates
were disabled; Dependabot version-update configuration is added by this PR.
The Dependabot alert API reported disabled (403); private vulnerability reporting
was also verified disabled.
The API reported **no rulesets**, main `protected: false`, and the main protection
endpoint returned not found.
This PR does not configure branch protection or account settings.

Owner setup after review/merge:

1. Require `Secret/privacy and static gates`, `CodeQL Python (redacted)` and the
   supported-platform test matrix on main. Require review of security configuration,
   actions, exceptions and dependency changes; disallow force-push/bypass as policy.
2. Enable Dependabot security updates/alerts and review available secret-scanning
   non-provider options in repository settings. Version-update PRs are configured
   here, but activation and vulnerability alerts must be verified after merge.
3. Keep account email privacy and "block pushes exposing my email" enabled if
   desired. The email API was inaccessible. A GitHub-signed, account-associated
   commit verified the noreply address used for repository-local future commits;
   no global Git config was changed. Historical identities remain exposed.
4. Enable private vulnerability reporting in repository settings, or configure a
   private reporting channel if unavailable. Decide whether historical privacy
   cleanup is appropriate.

## Tools and limitations

Pinned tools: Gitleaks 8.30.1 and actionlint 1.7.12 (MIT), pip-audit 2.10.1 and
Bandit 1.9.4 (Apache-2.0), cargo-audit 0.22.2 (Apache-2.0/MIT), CodeQL action v4
(MIT action wrapper; CLI/query use governed by GitHub's CodeQL terms, available for
this public repository). Gitleaks now receives security patches rather than new
features; periodically reassess detection-rule coverage. These tools have false
positives and false negatives; dependency data changes independently of commits.

Official references: [Gitleaks](https://github.com/gitleaks/gitleaks),
[pip-audit and its requirement-execution caveat](https://github.com/pypa/pip-audit),
[Bandit](https://bandit.readthedocs.io/en/latest/),
[actionlint](https://github.com/rhysd/actionlint),
[cargo-audit](https://github.com/RustSec/rustsec/tree/main/cargo-audit),
[CodeQL configuration](https://docs.github.com/en/code-security/reference/code-scanning/workflow-configuration-options).
Exact scope, outcomes and unscanned areas are in [the audit](docs/SECURITY_AUDIT.md).
